Install lightpack-C3 firmware

Flashes a fresh Lux et Portabilis V2 board straight from this page. Nothing to install on your computer — no Python, no toolchain, no USB-serial driver.

Board ESP32-C3 SuperMini Flash 4 MB Release V0.4-pre Connects over USB-C (native)
Checking your browser…

Before you start

  1. Use Chrome or Edge on a computer Firefox, Safari and every mobile browser lack the Web Serial API this page needs. There is no way around it — the fallbacks are linked at the bottom.
  2. Use a USB-C cable that carries data Charge-only cables enumerate nothing, and they are the usual reason no port shows up.
  3. Plug the board in — no buttons needed A blank C3 already sits in its ROM bootloader, so it should appear immediately. If it does not, see No port appears below.

Flash it

lightpack-C3 V0.4-pre factory image · 1.27 MB · ESP32-C3
This browser cannot install ESP devices. Open this page in Chrome or Edge on a desktop. This page must be served over https:// or localhost. See Running it locally below.

Click Install, pick the port when the browser asks, and leave the board plugged in until it says it is done — usually 20–40 seconds. Then the board reboots.

After it finishes

  1. Join the Wi-Fi hotspot Lightpack-Devkit First boot with no saved network raises this temporary access point for 60 seconds at a time; the configuration page opens by itself.
  2. Pick your own Wi-Fi network The board keeps it, and drops the hotspot.
  3. Open http://lightpack.local That is the full control page from then on. Buttons work without any browser: 1 click next mode, 2 clicks previous mode, 5 clicks power off, 3 s hold radio on/off.

Details

What exactly gets written to the board?

One merged factory image at offset 0x0, containing the whole boot chain:

RegionOffsetPurpose
Bootloader0x0Second-stage bootloader
Partition table0x8000Two 1.9375 MB OTA slots
OTA selector0xE000Makes the bootloader start app0
Application0x10000lightpack-C3 V0.4-pre

NVS is not touched, so this is also a safe recovery path for a board that misbehaves: presets, saved networks and the page login survive.

The exact same file, with checksums, is in FLASHING.md if you would rather flash it with esptool.

No port appears in the browser dialog
  • Hold BOOT, tap RESET, release BOOT. That forces the ROM download mode and is the fix in most cases.
  • Swap the cable. Charge-only USB-C cables are extremely common.
  • Check the board has power. A flat battery with no USB power shows nothing.
  • Close anything else holding the port — PlatformIO's monitor, the Arduino serial monitor, PuTTY. Web Serial cannot open a port another program owns.
  • Linux: add yourself to the dialout group and log back in.
  • macOS: no driver is needed for the C3's native USB; if the board has a separate USB-UART chip on a clone, only then is a driver required.
It says "Failed to connect" or the install stops part-way
  • Unplug, hold BOOT, plug back in, release BOOT, then retry.
  • Flashed images are verified before they are made bootable, so an interrupted install leaves the previous firmware running — retrying is safe.
  • If a board keeps failing, the fallback is the command line: esptool.py --chip esp32c3 write_flash 0x0 lightpack-C3-V0.4-pre-factory.bin (see FLASHING.md).
Running it locally, or with no internet

Web Serial only works on https:// or localhost, so opening install/index.html off disk will not work. Serve the repository root:

git clone https://github.com/machadoleonardo94/lux-et-tenebris.git
cd lux-et-tenebris
python -m http.server 8000

then open http://localhost:8000/install/.

Serve the repository root, not the install/ folder — the page fetches the firmware from Firmware/lightpack-C3/releases/, and it must be the same origin as the page. The installer component itself loads from a CDN on first use, so see install/README.md for the fully offline setup.

Why the browser instead of a helper script?

Because a blank board is the one case where the user has nothing installed yet. A Python script would mean requiring an interpreter, pip install esptool, and a driver conversation before anything happens; the ESP32-C3's native USB plus Web Serial removes all of it. The script-style routes still exist and are documented — they are just not the first thing to hand someone.

This is a pre-release. Known issues, including a dead touch-pad input on the reference board, are listed in the changelog. All user gestures work from the board's own BOOT switch, so the firmware is fully usable — just not what V0.3 promised.
