# 0.6 configuration schema

0.6 adds a device power layer and exposes the gyro-fade constants. The preset
format moves to **v3**; v2 slots are reported as incompatible rather than
misread.

## New fields

| Field | Range / default | Where | Notes |
|---|---|---|---|
| `budget` | 100–2000 mA, default **1000** | live config, **not** a preset | Worst-case white current ceiling: `budget / (leds × 60 mA) × 255`. Device property: cell, cable and strip length. |
| `rainbow_level` | 0–255, default **128** | rainbow + preset | Mode-local trim, applied before the global brightness. The rainbow is the only always-full-saturation mode. |
| `fade_decay` | 0.50–0.995, default 0.90 | gyro fade + preset | Gyro peaks kept per frame. |
| `fade_trigger` | 0.02–2.0, default 0.20 | gyro fade + preset | Gyro-z floor for the active state. |
| `fade_length_gain` | 0–40, default 20 | gyro fade + preset | Lit LEDs per unit of \|gyro x\| / \|gyro y\|. |
| `fade_length_z_gain` | 0–40, default 15 | gyro fade + preset | Lit LEDs per unit of \|gyro z\|. |
| `fade_length_base` | 0–40, default 10 | gyro fade + preset | Lit LEDs added to the active length. |
| `fade_power_gain` / `fade_power_base` | 0–10 / 0–50 | gyro fade + preset | Reserved brightness terms in the schema. |
| `fade_color_gain` | 1–20, default 7 | gyro fade + preset | Scales the gyro peaks into RGB. |
| `fade_idle_length` / `fade_idle_power` | 0–150 / 0–255 | gyro fade + preset | Stationary state. |

## 10 Hz guard

`power_guard_loop()` reads V_REG every 100 ms:

- below **3.70 V**: trim `power_guard_scale` by 5/255 (~2%) per tick;
- above **3.75 V**: recover 1/255 per tick;
- 255 means untouched. The trim scales the frame brightness only; the stored
  brightness is never changed, so the strip returns to it when the rail recovers.

The guard is a normal-operation aid, not a brown-out cure. Safe mode still follows
a real C3 reset.

## Advisory suggested limit

The state exports `power_suggested_ma`:

```
suggested = (V_off − 3700 mV) × 1000 / R_mohm     (clamped 100–2000 mA)
```

It comes from the last stress or sense result and is **advisory only**; the
firmware never writes it into the budget. A USB-assisted run overestimates, which
is why the page labels it as a suggestion.

## Power application order

`update_strip()` target brightness:

1. configured brightness;
2. budget ceiling for the active LED count (60 mA/LED worst case);
3. 10 Hz guard scale;
4. safe-mode 70% after a brown-out.

## Preset v3

`struct_preset` now carries the rainbow level and the ten fade fields: **39
fields**. The power budget is deliberately excluded. A v2 slot fails the length
and version check and is shown as `incompatible`; the live configuration and the
new keys load with defaults, so the board is not reset.

## Surfaces

- Device page: **Max current** under Brightness, **Level** under Rainbow flow, a
  **Gyro fade** section, and the guard/suggested line.
- USB console: `budget` on Shared, `rainbow_level` on Rainbow flow, the fade
  fields on Gyro fade; the budget is tagged `preset: false`.
- `@SET budget=…` and the new fields work through the existing `SET` path.
