These apply to every mode. The palette drives Solid color, the whip hump and the flame; the gyro-driven modes and Rainbow flow compute their own colour.

Palette

#ff00ff

Connect to read the strip length the firmware was built for.

Step flame

An impact lights the whole strip, then every LED keeps a fraction of its own brightness per frame. The far end goes dark first, so the flame reads as retreating toward the start.

Preview an impact

Injects a magnitude into the detector's latch, so the flame can be tuned without knocking the board. The detector's own counters are untouched.

Impact detector

Runs from loop() on a fixed cadence, independent of the selected mode. It works on the magnitude of the acceleration vector, learns a slow resting baseline, and reports one peak per impact.

Pulse whip

A half-sine hump leaves the start of the strip and travels outward. If the period is shorter than the crossing time, several humps coexist and their light adds up.

Rainbow flow

The starting LED gets a new random colour after a wait drawn between Min and Max, then that colour travels toward the far end. Every LED changes colour once per wait, whatever the speed.

Gyro fade

The gyro peaks decay each frame into a lit length and a colour. Decay, trigger, the three length terms, the colour gain and the idle state are tunable here.

Open Diagnostics for the live gyro numbers while the mode runs.

Presets

A slot holds the look: mode, colour, brightness, strip length, the impact detector, the flame, the whip, the rainbow (level included) and the gyro fade. The power budget is device-only and is not carried in a slot. Applying one also writes it as the boot configuration.

The export file is the same format the device page writes, so a preset can be moved between the browser page and this console unchanged. Import applies each preset and saves it into its slot; the board is left on the last one in the file.

Diagnostics

Everything the board reports about itself. This is also where the radio can be switched off: the USB link keeps working, which is the point of this console.

WiFi radio

Connect to read the radio state.

Switching the radio off leaves USB, the strip and every mode working. Switching it on joins the saved network in the background; this console never needs that join.

Saved networks

Two saved networks; with the radio on the board tries the primary, then the fallback. The password is written to the board and never read back.

Power stress test

Ramps the selected channels from off to the selected limit (or full brightness on a short strip) and records where the rail gives up. The board blanks the strip for five seconds first: unplug USB there to test the battery. Reconnect afterwards to read the result — it is stored in NVS, so the reconnect cannot lose it. The radio must be off; the USB link is enough.

Channels mA

Fast = 500 ms steps; unchecked = 2 s precise. Above 2000 mA is lab only: it exceeds the continuous benchmark and may force a brown-out on the 14500. The limit is clamped to 500–6000 mA. No rail guard disables the test's 3.0 V collapse stop so the run can find the absolute limit; it is lab-only and the normal 10 Hz guard is unaffected.

Connect to the board with the radio off to run a test.

Channel resistance

Lights N white LEDs at full brightness after a 5 s cable-removal window and reports the source resistance from the V_REG drop. Decoupled from the stress ramp, so a 1, 10, 20, 50, 100 LED sweep is quick. The current is the model (60 mA per white LED); drift in R across counts is the cell/model linearity.

100 white LEDs is ~6 A. The PMOS is rated 3.6 A continuous / 5 A max, 20 A pulses: 100 LEDs at 2 s is lab-only and above the continuous rating; use 200 ms for the sweep.

USB updater

Downloads the release from the web (the computer's connection) and writes the app over the existing USB control link. The board does not need internet. The strip is held off while the transfer runs; the status pixel heartbeats purple on progress, turns solid if it stalls, and blinks red three times on failure. Connect to the board first. NVS is untouched until the new slot is complete, so mode, palette, presets, networks and login survive.

Recovery (older board, or one that will not update): hold GPIO9 (BOOT) while plugging the board in or pressing RESET, release it when the port appears, then click Recovery and pick that port. It writes the same firmware through the ROM and keeps settings and presets.

The image is sent as base64 chunks on the same @ link, acknowledged by the board and written through Update.h. If it is interrupted, the board keeps running the image it booted with; retry, or use the browser installer. For the computer-side path without this page, use tools/usb_updater.py.
